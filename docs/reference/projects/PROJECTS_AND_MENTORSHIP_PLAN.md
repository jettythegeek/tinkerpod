# Projects and mentorship plan

Source PRD: sections 4, 7, 9, 10, 15, 19.

## Project workflow

Draft → Submitted → Under review → Needs improvement / Approved / Excellent / Rejected. Resubmission creates history rather than erasing prior mentor feedback.

Submission requirements are configured per project and may include text, image, video link/upload, document, URL, GitHub link, design screenshot, or robotics demo. Upload validation is server-side and storage is private.

## Pods

A Pod is a skill-based learning world—not merely a mentor group. It owns identity, pathway, courses, projects, mentors, live sessions, challenges, Pod XP/ranks, leaderboard scope, showcase, tools, and reports. Recommendations match age, level, interests, desired builds, mentor availability, and capacity. A Pod supports lead, support, reviewer, and instructor mentor roles. Admin override is allowed with an audit reason; membership history and reward history are retained.

## Mentor review

- Mentors see only assigned learners/submissions.
- Review uses project rubric, narrative feedback, optional recommended next step, and controlled final status.
- Priority review is derived from subscription entitlements.
- Reassignment, admin override, and status changes are audited and notify parent/child.

## Child safety

No unmonitored private chat in MVP. Feedback is retained and visible to the parent. Public showcase remains disabled; future publication requires explicit parent consent and admin moderation.
