# Handoff: P2.1 content schema reconciliation + public catalogue API

- Build package: `P2.1`
- Agent: Qoder
- Date: 2026-09-26
- Status: partial (catalogue API complete and verified; admin authoring suite blocked; Design-B schema ratified in DECISIONS.md 2026-09-26)

## Outcome

The repository contained two competing, half-finished P2.1 implementations ("Design A" `content_library` and "Design B" `learning_content`) that shared a migration timestamp and both created `tracks`, so a fresh migrate crashed and 64 tests failed. This pass consolidated on Design B, removed the Design-A artifacts, restored the missing production authorization policy, and shipped the read-only public catalogue API that was the actual undelivered P2.1 product feature. A parent-facing client can now read published tracks/courses; drafts and archived content are never visible, and unpublished slugs cannot be probed.

## Changed areas

- Reconciliation: deleted duplicate Design-A migration `2026_09_26_000001_create_content_library_tables.php` and 5 dead `app/Enums/*` orphan files; removed the `migrateFreshUsing` filter hack from `LearningContentTest`.
- Authorization: added `App\Policies\ContentPolicy` (active + `super_admin`/`admin`/`content_manager` may author; delete always denied; no `before()` bypass) and registered it for `Track`/`Course`/`Module`/`Lesson` in `AppServiceProvider`.
- Catalogue API (new): `TrackController`, `CourseController`, resources `TrackResource`/`CourseResource`/`CourseDetailResource`/`ModuleResource`/`LessonResource`, three public routes in `routes/api.php`, and `LearningCatalogueTest` (8 tests).
- Contract: `docs/api/openapi-v1.yaml` gained `/tracks`, `/courses`, `/courses/{slug}`.

## Database / API / contracts

- Kept schema: `2026_09_26_000001_create_learning_content_tables.php` (`tracks`, `courses`, `modules`, `lessons`, `content_publication_events`). No new migration this pass.
- Endpoints are public and read-only; response envelope `success`/`message`/`data` with `meta` + `links` on lists. Only `published` rows are returned. Filters: `pod`, `track`, `level` (`beginner|intermediate|advanced`), `age` (5–18, matched against `minimum_age`/`maximum_age`). `per_page` clamped 1–50.
- Course detail eager-loads the published subtree and never exposes lesson media bodies, storage paths, or any child/parent data. `access.requires_subscription` is fixed `true` for P2.1.
- Unknown and unpublished slugs share one `404` (`Course not found.`) so drafts cannot be probed by slug.

## Design and behavior

- Ratified deviation from the earlier task-spec wording (product call on 2026-09-26): shipped Design B uses `courses.learning_level` (was `experience_level`), `lessons.attachment_path` (was provider-neutral `attachment_url`), `courses.pod_id`/`track_id` as NOT NULL (was nullable), `modules.course_id`/`lessons.module_id` as `restrictOnDelete` (was `cascadeOnDelete`), and a `ContentWriter` publication flow with a `content_publication_events` audit table (was `PublishCourse`/`ArchiveCourse`). `DECISIONS.md` was updated to supersede the prior entries and records the accepted behavior change (no Pod-less draft course).

## Known limitations or blockers

1. **Isolated blocker (user chose to defer):** 5 `tests/Feature/Filament/LearningAuthoringTest` failures are Filament v4→v5 test-harness incompatibilities (`Text::getName` missing on `getFlatComponents()` nodes; URL-action `getActionFunction()` still present in v5) plus one Windows/NTFS limitation (local Flysystem disk cannot report unix `private` visibility, so the PDF-private test cannot pass on this OS). These are test-harness/environment issues, not confirmed production defects. No production behavior was changed to chase them; speculative v5 wiring edits were reverted.
2. **Schema decision (resolved — ratified).** Design B contradicted the earlier `DECISIONS.md` entries; product ratified Design B on 2026-09-26 and `DECISIONS.md` now records the reversal, including the accepted consequence that a course cannot be saved before its Pod/track is chosen and that non-empty modules/lessons cannot be deleted.
3. **Unrelated pre-existing lint:** `PlanResource`, `SubscriptionResource`, `TransactionResource` have `fully_qualified_strict_types` Pint violations outside P2.1 scope; not touched.
