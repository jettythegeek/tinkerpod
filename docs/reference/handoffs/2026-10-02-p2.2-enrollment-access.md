- Build package: `P2.2`
- Agent: Qoder
- Date: 2026-10-02
- Status: complete

## Outcome

A parent can enroll their child in eligible published courses via `POST /api/v1/parent/children/{child}/enrollments`. The system enforces age eligibility, Pod membership, and subscription entitlement server-side; free-preview courses bypass the subscription check. The `GET /api/v1/parent/children/{child}/available-courses` endpoint returns a filtered, personalized catalogue. Enrollment is idempotent: duplicate requests return the existing record without error.

## Database/API/contracts

- New table `course_enrollments`: id, child_id FK, course_id FK, enrolled_by_parent_id FK, source varchar(20), status varchar(20), started_at, completed_at, timestamps. Unique `(child_id, course_id)`. Restrict deletes (history preservation).
- All FK columns are `restrictOnDelete` — child/course/parent cannot be deleted while an enrollment exists.
- Endpoints authenticated via Sanctum bearer + ChildPolicy ownership check.
- 403 responses carry `errors.reason` machine codes: `not_published`, `age_mismatch`, `no_pod_membership`, `no_subscription`.

## Design and behavior

No visual surface. Behavior follows SUBSCRIPTION_AND_PAYMENT_PLAN access-rules model:
- Access = published + age + Pod membership + subscription (or free_preview bypass).
- Existing enrollments persist after subscription expiry (blocking lesson playback is P2.3).
- Pod membership requirement makes the P1.3A onboarding flow a prerequisite for enrollment.

## Decisions and assumptions

- `plan.access_rules` JSON structure reserved for future use; P2.2 implements `pod_membership` rule only.
- `source` enum includes `camp`/`school` values per PRD schema but no logic branches on them yet.
- Free-preview bypasses subscription but NOT Pod/age checks (product decision from PRD SS16).

## Known limitations or blockers

- No unenrollment/withdrawal endpoint (future need; not P2.2 scope).
- No enrollment status transitions (completed/paused/cancelled paths deferred to P2.3).
- Filament admin: no resource for browsing/managing enrollments yet (P2.7 or admin polish).
- Same 5 pre-existing Filament v5/Windows blocker from P2.1 (unrelated).
