# What is a Pod?

A **Pod** is a structured learning community where kids learn a specific tech skill, complete projects, get mentor support, earn badges/ranks, and compete on leaderboards.

In simple terms:

> A Pod is where a child belongs, learns, builds, competes, and grows.

So the Pod contains:

1. **A skill focus**
2. **A learning pathway**
3. **Courses**
4. **Projects**
5. **Mentors**
6. **Live classes**
7. **Challenges**
8. **Badges**
9. **Ranks**
10. **Leaderboard**
11. **Progress system**
12. **Community/showcase**
13. **Recommended kits/tools**

That is much richer.

# Gamification: badges, ranks, points and leaderboard

Yes. We should add ranks.

Badges alone are good, but ranks make the child want to climb.

The gamification system should have four parts:

1. **XP Points**
2. **Badges**
3. **Ranks**
4. **Leaderboards**

---

# 1. XP Points

XP means experience points.

Kids earn XP for actions.

Example:

| Action                           |          XP |
| -------------------------------- | ----------: |
| Complete a lesson                |       10 XP |
| Complete a quiz                  |       15 XP |
| Score above 80% in quiz          | 10 bonus XP |
| Submit a project                 |       50 XP |
| Project approved                 |      100 XP |
| Project rated excellent          |      150 XP |
| Attend live class                |       25 XP |
| Complete weekly challenge        |       75 XP |
| Maintain 7-day streak            |       50 XP |
| Help/participate in pod activity |       20 XP |
| Complete a course                |      200 XP |
| Complete a Pod level             |      500 XP |

XP drives ranking and leaderboard position.

# Should children join one Pod or many Pods?

For MVP, I recommend:

## Basic Plan

1 active Pod.

## Standard Plan

1 active Pod + access to selected extra courses.

## Premium Plan

2 active Pods or 1 active Pod + premium mentor support.

## Admin

Can manually add a child to multiple Pods.

Why?

If you allow too many Pods immediately, the child may become scattered. It is better to give them a focused path first.

Later, kids can unlock additional Pods.

Example:

> Complete Coding Pod Level 2 to unlock AI Pod basics.

This makes the platform more gamified.

# How Pods, Courses and Tracks relate

We should simplify it like this:

## Track

Broad category.

Example:

* Technology
* Creativity
* Innovation

But we may not even need tracks strongly in the user-facing app.

## Pod

The main user-facing learning world.

Example:

* Coding Pod
* AI Pod
* Robotics Pod
* Design Pod
* Young Founders Pod

## Course

Structured learning inside a Pod.

Example:

Inside Coding Pod:

* Scratch Starter
* Game Builder
* Web Basics

## Module

Sections inside a course.

## Lesson

Individual lesson.

## Project

What the child builds.

So the hierarchy becomes:

> Pod → Courses → Modules → Lessons → Projects → Badges/Ranks

This is clear.

In the app, children should mostly see **Pods**, not “tracks.”

Parents can see:

> Choose a Pod for your child.

That is more branded and simpler.
